# OSM surroundings — make generated tracks recognizable

Date: 2026-09-24 · Status: approved design, awaiting spec review · Closes #2 (mini map)

## Problem

A play-test of a Sisseln loop generated by `osm-track.html` produced a valid, drivable track,
but the player did not recognize Sisseln. Only the road shape comes from OpenStreetMap:
the surroundings are procedural forest and tents, the fixed chase camera looks from the
south-east (north is up-left on screen), and staircase rasterization turns diagonal streets
into S-bends.

## Goal and success criterion

Driving a lap of a generated loop, the player knows where they are in the village: buildings
and side streets are where they are in reality, a north-up minimap shows the position, and the
current street name is on screen.

**Success:** the user play-tests a Sisseln loop with surroundings and recognizes it.

## Scope

In scope: surroundings (buildings, side streets), north-up minimap, street-name HUD, a smoother
default raster mode. Out of scope: water, land use, real trees, elevation, drivable side streets,
changes to the `?map=` tile codec, i18n (parked separately).

The minimap is built generic (loop + car, every track); OSM tracks add streets and buildings to
it. That closes #2.

## Architecture and data flow

```
osm-track.html ── Play / Copy link ──▶ index.html?map=<tiles>&osm=<s>,<w>,<n>,<e>,<mpc>,<offX>,<offZ>
                                            │
main.js ── builds track from ?map= (unchanged, immediate)
        └─ if &osm=: fetchOverpass(streets + buildings)  ── async ──▶ OsmScene meshes + OsmHud data
```

- **Link.** `osm-track.html` appends `&osm=` with the bbox, metres per cell and the grid offset
  `loopCenter()` applied. The game places OSM metres on the tile grid with
  `x_world = (x / mpc − offX + 0.5) · S`, `z_world = (−y / mpc − offZ + 0.5) · S`,
  where `S = CELL_RAW · GRID_SCALE` and `(x, y)` come from `makeProjection(bbox)`.
- **Fetching.** `fetchOverpass(query)` — mirror list, per-mirror timeout, `localStorage` cache —
  moves from `osm-track.html` into `js/OsmTrack.js` (still no three.js import) and is used by both
  the page and the game. The query additionally returns `way["building"]` in the bbox.
- **New `js/OsmScene.js`** (three.js): OSM JSON → one merged building mesh, one merged side-street
  mesh, added to the scene.
- **New `js/OsmHud.js`**: minimap canvas + street-name pill (DOM).
- **Upstream touch points** (no-ops without `&osm=`):
  - `main.js`: parse `&osm=`, start the fetch in parallel with track building, add meshes and
    HUD data when it resolves, call `hud.update(carPosition, heading)` per frame.
  - `Track.js`: `buildTrack( scene, models, customCells, { osm } )` — with `osm`, procedural
    forest and tents are placed only outside the OSM bbox; inside it stays plain grass.

## Components

### `OsmScene.js`

- **Buildings:** footprints extruded to `building:levels × 3 m`, default 6 m, converted with the
  world-per-metre factor `S / mpc`. Flat pastel look matching the kit: wall colour from 4–5 tones
  chosen by a hash of the way id, lighter flat top. All buildings merged into one mesh.
- **Track clearance:** a building whose footprint overlaps any track cell is dropped (tiles sit
  up to half a cell off the real street).
- **Side streets:** every way not on the loop becomes a flat asphalt ribbon, 0.5 cell wide, just
  below the tile surface. It ends at the track wall; side streets are not drivable.

### `OsmHud.js`

- **Minimap:** top-right below the GitHub button, 190×130, north-up, style like Aerodrome Apex.
  Static layer (streets faint, buildings, loop in yellow) drawn once to an offscreen canvas;
  car arrow drawn per frame. Without OSM data it shows loop + car only (generic, closes #2).
  On narrow screens it shrinks so it does not cover the lap timer.
- **Street name:** pill bottom-centre above `#game-nav`, showing the nearest named way within one
  cell of the car; fades out between named streets. Lookup through a coarse spatial grid of way
  segments so it is cheap per frame.

### Smoother geometry (`OsmTrack.js`, `osm-track.html`)

- New raster mode **Auto**, the page default: per segment use the one-corner (`L`) path; where
  that path would hit a cell already in the loop, use the staircase path for that segment.
  Stairs and One corner remain selectable.

## Error handling

- Overpass: mirror failover and cache as today; if all fail the track plays normally and a small
  note "Surroundings unavailable" appears.
- `&osm=` that is malformed (non-numeric, wrong arity) or spans more than 0.1° in either axis is
  ignored — plain track, no crash.
- Budget: above ~20 000 building triangles, buildings farthest from the loop are dropped first.

## Testing

- **Node** (`test/osm-*.test.mjs`, saved Sisseln Overpass response as fixture):
  - Auto raster: no duplicates/shortcuts; corner count ≤ stairs on the same input.
  - Building filter drops footprints overlapping track cells, keeps the rest.
  - `&osm=` parsing accepts valid input, rejects malformed and oversized.
  - Metres→world transform puts the loop's own OSM nodes inside their track cells.
  - Street lookup returns the right name (e.g. "Hauptstrasse") for a point on that street.
- **Headless** (renderer stubbed, like the track-picker test): minimap canvas draws; the
  street-name pill updates for a scripted car position.
- **Manual:** play-test a Sisseln loop with surroundings.

## Constraints kept

Static files only, no bundler or `package.json`; `OsmTrack.js` stays three.js-free; default
track and editor unchanged; best-lap storage keyed by `?map=` unchanged (the `&osm=` part does
not affect it).
